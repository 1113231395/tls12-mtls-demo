# TLS 1.2 mTLS C Demo 设计

## 1. 背景与目标

依据 GB/T 47873-2026 第 7.1.1 条，车载终端与平台通过不受保护的网络通信时，应采用 TLS 1.2 及以上版本或 TLCP，对通信实体进行身份鉴别，并保证通信数据的完整性和机密性。标准还要求平台在建立连接前对车载终端进行身份鉴别。

本项目提供一个可在 Linux 上运行的纯 C Demo，以 OpenSSL 完成双向 TLS 1.2（mTLS）握手，并通过一次字符串请求与回显响应打通完整流程。Demo 用客户端证书代表车载终端身份，用服务端证书代表平台身份。

## 2. 范围

项目包含：

- 一个阻塞式 TCP/TLS 服务端，可顺序处理多个客户端连接。
- 一个阻塞式 TCP/TLS 客户端，每次运行发送一条字符串并接收回显。
- 一个测试证书生成脚本，生成根 CA、服务端证书和客户端证书。
- 一个 Makefile，用系统 OpenSSL 编译客户端和服务端。
- 使用说明和自动化测试脚本。

项目不包含 JT/T 808 报文编解码、生产证书管理、证书吊销在线检查、连接并发模型、断线重连或业务层终端鉴权。

## 3. 方案选择

采用 OpenSSL 阻塞式 mTLS Echo 方案。该方案直接展示 TCP 建连、TLS 握手、双向证书认证、加密读写和正常关闭，代码规模适合教学和集成验证。

未采用以下方案：

- 单向 TLS 加业务层终端认证：符合标准允许的组合思路，但会引入额外认证协议，不利于聚焦 TLS 流程。
- 非阻塞 TLS 或事件循环：更适合生产服务，但会增加状态机复杂度，不属于本 Demo 的目标。

## 5. TLS 与证书设计

客户端和服务端均将 OpenSSL 最低及最高协议版本设为 TLS 1.2，从而拒绝 TLS 1.0、TLS 1.1 和 TLS 1.3。此限制用于验证明确的 TLS 1.2 流程，不代表生产环境应禁用 TLS 1.3。

测试 PKI 包含：

- 一个自签名测试根 CA。
- 一个由该 CA 签发的服务端证书，扩展用途为 `serverAuth`，SAN 包含 `DNS:localhost` 和 `IP:127.0.0.1`。
- 一个由该 CA 签发的客户端证书，扩展用途为 `clientAuth`。

服务端加载自己的证书和私钥，信任测试根 CA，并使用 `SSL_VERIFY_PEER | SSL_VERIFY_FAIL_IF_NO_PEER_CERT` 强制验证客户端证书。客户端加载自己的证书和私钥，信任测试根 CA，验证服务端证书链，并校验连接目标 `localhost` 的主机名。

握手成功后，双方输出协商出的协议版本、密码套件和对端证书主题。任何证书链、用途、有效期或主机名验证失败都会终止握手。

生成的私钥和证书仅供本机 Demo 使用。脚本重复运行时重新生成测试 PKI，`certs/` 通过 `.gitignore` 排除。

## 6. 数据协议与流程

TLS 建立后，应用消息格式为：

```text
+------------------------+----------------------+
| 4-byte unsigned length | payload bytes        |
| network byte order     | length bytes         |
+------------------------+----------------------+
```

载荷是命令行提供的字符串，不携带结尾空字符，长度上限为 4096 字节。接收端先完整读取 4 字节长度，再按声明长度完整读取载荷。长度为 0 或超过上限均视为协议错误。

客户端流程：

1. 创建 TCP 连接并连接 `localhost:8443`。
2. 创建客户端 TLS 上下文并加载 CA、客户端证书和私钥。
3. 设置服务端主机名校验并执行 TLS 握手。
4. 发送一条长度前缀字符串。
5. 接收并显示服务端回显。
6. 执行 TLS 关闭并释放资源。

服务端流程：

1. 创建监听套接字并监听 `8443`。
2. 创建服务端 TLS 上下文并加载 CA、服务端证书和私钥。
3. 接受 TCP 连接并执行要求客户端证书的 TLS 握手。
4. 接收并显示一条字符串，再按相同格式原样返回。
5. 关闭当前 TLS 连接，继续等待下一个客户端。
6. 收到 `SIGINT` 后停止监听并释放资源。

TLS 不保留应用消息边界，因此所有固定长度字段和载荷均通过循环调用 `SSL_read` 或 `SSL_write` 处理短读、短写及 `SSL_ERROR_WANT_READ`、`SSL_ERROR_WANT_WRITE`。

## 7. 错误处理

以下错误会产生清晰的标准错误输出和非零退出状态：

- OpenSSL 初始化或 TLS 上下文创建失败。
- CA、证书或私钥文件无法加载。
- 证书与私钥不匹配。
- 地址解析、套接字创建、绑定、监听或连接失败。
- TLS 握手失败或对端证书验证失败。
- 消息长度非法、连接提前关闭或 TLS 读写失败。

OpenSSL 失败路径输出错误栈；系统调用失败路径输出对应的系统错误。所有路径均关闭已创建的 TLS 对象、TLS 上下文和文件描述符。服务端只结束当前失败连接，不因单个客户端握手失败而退出。

## 8. 构建与运行

Makefile 优先通过 `pkg-config openssl` 获取编译和链接参数，并提供适用于常见 Linux OpenSSL 安装的回退参数。编译启用 C11、常用警告，并将警告视为错误。

构建产物为 `bin/tls_server` 和 `bin/tls_client`。两个程序使用 `getopt_long` 解析参数，并提供 `--help`：

```text
bin/tls_server [--port PORT] [--ca FILE] [--cert FILE] [--key FILE]
bin/tls_client [--host HOST] [--port PORT] [--verify-name NAME]
               [--ca FILE] [--cert FILE] [--key FILE] MESSAGE
```

服务端默认监听 `8443`，默认使用 `certs/ca.crt`、`certs/server.crt` 和 `certs/server.key`。客户端默认连接 `localhost:8443`，默认校验名称 `localhost`，并使用 `certs/ca.crt`、`certs/client.crt` 和 `certs/client.key`。显式的路径和名称参数用于集成环境及负面测试，不提供关闭证书校验的选项。

典型流程为：

1. 运行证书生成脚本。
2. 执行 `make`。
3. 在一个终端启动服务端。
4. 在另一个终端运行客户端并提供字符串。
5. 确认双方报告 TLS 1.2、证书身份和一致的回显内容。

## 9. 验证策略

自动化测试脚本覆盖：

- 正常 mTLS 握手及字符串回显。
- 客户端未提供证书时，服务端拒绝握手。
- 客户端信任错误 CA 时，客户端拒绝服务端证书。
- 客户端校验错误主机名时，客户端拒绝连接。
- 正常连接协商结果确认为 `TLSv1.2`。
- 超长输入在发送前被客户端拒绝。

测试脚本负责启动和停止临时服务端进程，并在退出时清理运行期文件。未提供客户端证书的负面场景使用 OpenSSL 命令行客户端触发；错误 CA 和错误主机名场景使用 Demo 客户端的参数触发。测试证书可以保留供人工运行，不提交到版本库。

## 10. 完成标准

满足以下条件即视为 Demo 完成：

- 在具备 C 编译器、Make、OpenSSL 开发包和 OpenSSL 命令行工具的 Linux 环境中可从零构建。
- 证书脚本可生成用途和 SAN 正确的测试证书。
- 客户端与服务端只能使用 TLS 1.2 完成 mTLS 握手。
- 正常字符串请求获得完全一致的回显。
- 缺少或不受信任的客户端证书无法连接。
- 不受信任或名称不匹配的服务端证书无法连接。
- 自动化测试全部通过，README 中的手工流程可复现。
